# ActiveJ JSON-RPC

JSON-RPC 2.0 for the ActiveJ platform, in two layers:

- the **envelope** — an immutable message model (request, notification, response, error, batch), a decoder
  over a contiguous `byte[]` that leaves `params` / `result` / `error.data` undecoded, and a deterministic
  encoder;
- the **service layer** — four annotations, a `JsonRpcDispatcher` that serves an annotated interface, a
  `JsonRpcClient` whose `proxy(...)` calls one, and a transport SPI to plug a wire into.

**No transport ships here.** The SPI is the seam; implementing it is a separate concern.

This module is a part of ActiveJ platform.

## Maturity

**Experimental — `extra/` modules are not production-ready.** This module lives under `extra/`, which
is profile-gated and whose per-module maturity is an explicitly open question for the platform. Treat
it as experimental: the API may change without a deprecation cycle, and the default `mvn verify` does
not build or test it at all.

## How this differs from `activej-rpc`

`activej-jsonrpc` is a JSON-RPC 2.0 text protocol — envelope, dispatch and a typed client proxy — with **no
transport of its own**, whereas `activej-rpc` (`cloud-rpc`) is a full binary RPC client/server stack,
transport included.

Concretely, this module contains no `ByteBuf` and no bytecode generation anywhere, and the two layers differ
in what else they may touch:

| Packages | Reactor / `Promise` | Testable without an eventloop |
|---|---|---|
| `io.activej.jsonrpc`, `io.activej.jsonrpc.impl` — the envelope | **no** | yes — a synchronous codec over `byte[]` |
| `io.activej.jsonrpc.service`, `io.activej.jsonrpc.transport` — the service layer | yes, and reactor-confined | no |

`ModuleBoundaryTest` enforces that split by package, not by module: a `Promise` or `Reactor` import in the
envelope packages still fails the build. Everything else the guard forbids — `ByteBuf`, `HttpRequest`,
`ChannelSupplier`, codegen, `activej-rpc`, `slf4j` — stays forbidden module-wide.

Binding an interface to the wire is done by `java.lang.reflect.Proxy` and reflection resolved **once at
construction**, not by generated bytecode: a JSON-RPC peer is bounded by its JSON parsing, and a codegen
dependency would buy nothing measurable at that scale.

## The contiguous-`byte[]` contract

The decoder takes one contiguous `byte[]` holding the whole envelope. This is a hard contract rather
than a convenience: an undecoded payload is an index pair into that exact array, and the underlying
parser's index space does not survive a buffer refill. A transport whose bytes arrive in pieces must
join them before decoding.

## Worked example

### Decode a request

`method` and `id` are decoded; `params` is deliberately left as raw bytes until you know what it
should be.

```java
byte[] envelope = """
    {"jsonrpc":"2.0","id":1,"method":"sum","params":[1,2,3]}""".getBytes(UTF_8);

JsonRpcInput input = JsonRpcDecoder.decode(envelope);

switch (input) {
    case JsonRpcRequest request -> {
        assertEquals("sum", request.method());                   // decoded
        assertEquals(new JsonRpcId.Num(1), request.id());        // decoded

        // `params` is NOT decoded yet — decode it once you know what it should be
        List<Integer> params = request.params().decode(LIST_OF_INT);
        assertEquals(List.of(1, 2, 3), params);
    }
    case JsonRpcNotification notification -> fail("no response may be built for " + notification);
    case JsonRpcResponse response -> fail("a peer answering us: " + response);
    case JsonRpcMalformed malformed -> fail("render malformed.toResponse(): " + malformed);
    case JsonRpcBatch batch -> fail("one outcome per element: " + batch);
}
```

`decode` **never throws** for malformed input. A failure arrives as `JsonRpcMalformed` carrying the
error object and the id if one was recoverable — a batch needs one outcome per element, which an
exception cannot express.

### Answer it

```java
JsonRpcPayload result = JsonRpcPayload.encoded(JsonCodecs.ofInteger(), 6);
byte[] bytes = JsonRpcEncoder.encode(JsonRpcResponse.ofResult(id, result));

assertEquals("{\"jsonrpc\":\"2.0\",\"id\":1,\"result\":6}", new String(bytes, UTF_8));
```

### Fail it

```java
byte[] bytes = JsonRpcEncoder.encode(JsonRpcResponse.ofError(id, JsonRpcErrors.INVALID_PARAMS));

assertEquals("{\"jsonrpc\":\"2.0\",\"id\":1,\"error\":{\"code\":-32602,\"message\":\"Invalid params\"}}",
    new String(bytes, UTF_8));
```

An application-defined code must stay out of the reserved `-32768 … -32000` range. Decoding is
deliberately more permissive: a peer's reserved code is kept verbatim, because discarding it would
throw away exactly what the peer meant to say.

```java
JsonRpcError mine = JsonRpcErrors.of(1001, "Insufficient funds");     // fine
assertEquals(1001, mine.code());

assertThrows(IllegalArgumentException.class,
    () -> JsonRpcErrors.of(-32601, "my own error"));                  // reserved range

// decoding is deliberately permissive: a peer's reserved code is kept verbatim
JsonRpcInput peer = JsonRpcDecoder.decode("""
    {"jsonrpc":"2.0","id":1,"error":{"code":-32601,"message":"Method not found"}}""".getBytes(UTF_8));
assertEquals(-32601, ((JsonRpcResponse) peer).error().code());
```

### A notification produces nothing

There is no method anywhere in this module that builds a response from a `JsonRpcNotification` — the
type has no `id` component at all. "A notification produces no response" is a compile-time fact, not
a runtime check.

```java
byte[] bytes = JsonRpcEncoder.encode(JsonRpcOutput.none());

assertEquals(0, bytes.length);          // zero bytes — NOT "[]", which on the wire means -32600
assertArrayEquals(new byte[0], bytes);
```

### Batches

```java
JsonRpcInput input = JsonRpcDecoder.decode(batchBytes);
byte[] out = new byte[0];

if (input instanceof JsonRpcBatch batch) {
    List<JsonRpcMessage> responses = new ArrayList<>();
    for (JsonRpcDecoded element : batch.elements()) {
        switch (element) {
            case JsonRpcRequest request -> responses.add(JsonRpcResponse.ofResult(
                request.id(), JsonRpcPayload.encoded(JsonCodecs.ofInteger(), 3)));
            case JsonRpcNotification ignored -> { }                     // no response
            case JsonRpcMalformed m -> responses.add(m.toResponse());    // one bad element != bad batch
            case JsonRpcResponse ignored -> { }
        }
    }
    // a batch renders as an array even at size 1; no responses at all renders as nothing
    out = JsonRpcEncoder.encode(
        responses.isEmpty() ? JsonRpcOutput.none() : JsonRpcOutput.batch(responses));
}
```

Three rules worth stating, because they are the ones most often implemented wrongly:

- An **empty** input array `[]` is not a batch — it decodes to a single `-32600`, rendered as one
  object, not an array.
- A batch of **only notifications** produces **no response document at all**, distinct from `[]`.
- Response **order is not guaranteed** and must not be relied on. Correlation is by `id` alone.

### Bounds

Three limits ship enabled. You raise them with a system property; you never enable them.

| Setting key | Default | Refusal |
|---|---|---|
| `JsonRpcLimits.maxBodySize` | `1mb` | `-32001 Request too large` |
| `JsonRpcLimits.maxBatchSize` | `100` | `-32002 Batch too large` |
| `JsonRpcLimits.maxJsonDepth` | `64` | `-32003 Nesting too deep` |

```bash
java -DJsonRpcLimits.maxBodySize=4mb -DJsonRpcLimits.maxBatchSize=500 ...
```

The size bound is meant to be applied **while** you accumulate, not after — a bound checked against
an array you have already allocated arrives after the allocation it was supposed to prevent. Read
`JsonRpcLimits.MAX_BODY_SIZE` in your accumulation loop.

The depth bound is checked by a scan over your array **before** any parsing, because the underlying
parser's `skip()` recurses once per nesting level and would exhaust the stack before any in-parser
check could fire.

### Payload lifetime

A decoded payload holds a reference to **your** array plus a `[start, end)` pair — it does not copy.

```java
// retaining a payload keeps the WHOLE envelope array reachable
byte[] independent = request.params().toByteArray();   // the escape hatch
assertArrayEquals("[1,2,3]".getBytes(UTF_8), independent);

// mutating the envelope after decoding invalidates every payload derived from it
assertEquals(7, request.params().size());
```

This module never mutates your array, and never retains it beyond what a payload you hold keeps
alive.

## The service layer

An annotated Java interface is the whole contract. `JsonRpcDispatcher` serves it,
`JsonRpcClient.proxy(...)` calls it, and neither half asks you for a line of routing, correlation or
serialization code.

Both are reactor-confined — every public method begins with `checkInReactorThread(this)` — and every codec,
descriptor and contract is resolved **once, at construction**: never per connection, per request or per call.

### Declare the interface

```java
@JsonRpcService("user")
public interface UserApi {
    /** The identified call. */
    @JsonRpcMethod("get")
    Promise<User> getUser(@JsonRpcParam("id") long id);

    /** The notification — no response element is ever produced for it. */
    @JsonRpcNotification("touch")
    void touch(@JsonRpcParam("id") long id);
}
```

`User` is an ordinary `record` — `activej-json` derives its codec by reflection, so nothing here registers
anything.

| Annotation | On | What it means |
|---|---|---|
| `@JsonRpcService("user")` | the interface | the wire-name prefix for every method it declares; `""` for none |
| `@JsonRpcMethod("get")` | a method | an identified call. Returns `Promise<T>`; a dispatcher also accepts a synchronous `T`, a proxy refuses one — answering it would mean blocking the reactor |
| `@JsonRpcNotification("touch")` | a method | a call with no `id` and no response ever. Returns `void` or `Promise<Void>` |
| `@JsonRpcParam("id")` | a parameter | its name in named `params`. **Required**, with no reflective fallback: this build carries no `-parameters` flag, so a parameter's reflective name is `arg0` and a fallback onto it would make an unrelated compiler flag load-bearing for the wire contract |

The wire name is the service's prefix, a dot, and the method's own name:

```java
JsonRpcDispatcher dispatcher = JsonRpcDispatcher.builder(Reactor.getCurrentReactor())
    .withService(UserApi.class, new UserApiImpl())
    .build();

// the service's prefix, a dot, and each method's own name
assertEquals(Set.of("user.get", "user.touch"), dispatcher.wireNames());
```

An interface that breaks the contract is refused **at `build()`**, before a dispatcher exists and before any
transport could have been constructed — and one exception names **every** violation, not the first: a
contract with four mistakes in it takes one run to fix, not four.

#### The wire name is a commitment

Read this before writing your first interface.

`@JsonRpcMethod` and `@JsonRpcNotification` both default `value()` to `""`, which falls back to **the Java
method's own name**. Write `@JsonRpcMethod` with no value on a method called `getUser` and `getUser` is what
goes on the wire — a Java identifier, published as protocol.

Rename that method to `fetchUser` later and every peer keeps calling `getUser`, which now answers `-32601`.
**Nothing anywhere fails to compile**, because nothing ties a Java name to a wire name once the annotation has
defaulted: an IDE rename is a wire-format change wearing a refactoring's clothes, and the first sign of it is
a peer's error rate.

The mitigation is one word — give the annotation an explicit value:

- `@JsonRpcMethod("get")` — the wire name is `user.get` no matter what the Java method is called;
- `@JsonRpcMethod` — the wire name is whatever the Java method is called today.

Use the first form in any interface whose wire name must stay stable. The same care applies to two other
names this layer publishes: a `@JsonRpcParam` value in `NAMED` style, and — since `activej-json` derives a
`record`'s codec from its **component names** in **canonical constructor order** — the components of any
`record` used as a parameter or a result.

#### Renaming *is* a compile error on both sides

What the annotation defaults away is the wire name, and nothing else. The method itself stays an ordinary
Java signature: rename it and the implementing class no longer implements the interface, while
`client.proxy(UserApi.class).getUser(42)` no longer resolves. This layer adds **no mechanism that weakens
that** — no string-keyed lookup on the caller's side, no dynamic invocation by name.

That is asserted rather than claimed:
[`JsonRpcRenameCompilationTest`](src/test/java/io/activej/jsonrpc/service/JsonRpcRenameCompilationTest.java)
drives the JDK's own compiler over three throwaway sources and asserts that the unmodified pair compiles,
that renaming the implementation does not, and that renaming the call site does not either.

### Serve it

```java
JsonRpcDispatcher dispatcher = JsonRpcDispatcher.builder(Reactor.getCurrentReactor())
    .withService(UserApi.class, new UserApiImpl())
    .build();

byte[] response = await(dispatcher.dispatch("""
    {"jsonrpc":"2.0","id":1,"method":"user.get","params":[42]}""".getBytes(UTF_8)));

assertEquals("{\"jsonrpc\":\"2.0\",\"id\":1,\"result\":{\"id\":42,\"name\":\"user-42\"}}",
    new String(response, UTF_8));
```

`dispatch` is **total**: it never completes its promise exceptionally — not for a truncated document, not for
an unknown method, not for a throwing implementation. Every failure is a JSON-RPC error *document*, so a
transport author writes `dispatch(...).then(this::respond)` with no failure branch. A zero-length answer means
there is no response document at all (a notification, an all-notification batch, or an inbound response), and
that is not `[]` and not `{}`.

An unknown method answers `-32601` **without invoking anything**, and `params` that fail to decode answer
`-32602` — also without invoking anything, and without echoing the offending input.

There is deliberately no `close()`: the dispatcher owns no resource and keeps no in-flight registry, so a
`close()` would be a promise it could not keep. Cancelling server-side work when a connection drops needs
knowledge only a transport has.

### Call it

```java
JsonRpcDispatcher dispatcher = JsonRpcDispatcher.builder(Reactor.getCurrentReactor())
    .withService(UserApi.class, new UserApiImpl())
    .build();

// no transport ships in this module — this is the in-memory double the module's own tests use
JsonRpcTransport transport = InMemoryTransport.create(dispatcher::dispatch);
JsonRpcClient client = JsonRpcClient.builder(Reactor.getCurrentReactor(), transport).build();

UserApi api = client.proxy(UserApi.class);

Promise<User> user = api.getUser(42);   // {"jsonrpc":"2.0","id":1,"method":"user.get","params":[42]}
api.touch(42);                          // {"jsonrpc":"2.0","method":"user.touch","params":[42]}

assertEquals(new User(42, "user-42"), await(user));
client.close();
```

`proxy(...)` returns a `java.lang.reflect.Proxy`: the contract is validated in full at `proxy(...)` time — with
one client-only rule on top of the dispatcher's, that a synchronous `T` is refused — and the proxy is cached
per interface, so repeat calls repeat neither reflection nor codec resolution. One call is exactly one document; identifiers are
`JsonRpcId.Num`, monotonic from 1; a notification allocates no identifier and registers nothing.

Correlation is by `id` **alone** — responses may arrive in any order, and §6 guarantees none. A response whose
`id` matches no pending call is ignored silently; the correlation entry is removed *before* its payload is
decoded, so a result that fails to decode still leaves the table empty. `inFlightCount()` is the diagnostic
that makes "the table is empty" an assertion rather than an inference.

`equals`, `hashCode`, `toString` and any unannotated `default` method are answered **locally** and emit no
document. `close()` completes every pending call with `AsyncCloseException` and is idempotent; a close
originating at the peer takes the same path with the transport's cause; after either, a further call fails
immediately, hands nothing to the transport and records nothing.

Inbound documents the client did not ask for go to a peer handler, whose default answers a request `-32601`
and ignores a notification. A `JsonRpcDispatcher` implements the peer-handler interface directly, so
`withPeerHandler(dispatcher)` is the whole of the server&rarr;client direction.

### A deliberate error, and an accidental one

```java
JsonRpcDispatcher dispatcher = JsonRpcDispatcher.builder(Reactor.getCurrentReactor())
    .withService(PaymentsApi.class, new PaymentsApiImpl())
    .build();

// deliberate: the service's own code, message and `data` reach the peer verbatim
byte[] deliberate = await(dispatcher.dispatch("""
    {"jsonrpc":"2.0","id":1,"method":"payments.charge","params":[1000]}""".getBytes(UTF_8)));
assertEquals("{\"jsonrpc\":\"2.0\",\"id\":1,\"error\":{\"code\":429,\"message\":\"Too many requests\"}}",
    new String(deliberate, UTF_8));

// accidental: -32603 and nothing else. No class name, no message, no `data`, no stack frame
byte[] accidental = await(dispatcher.dispatch("""
    {"jsonrpc":"2.0","id":2,"method":"payments.charge","params":[1]}""".getBytes(UTF_8)));
assertEquals("{\"jsonrpc\":\"2.0\",\"id\":2,\"error\":{\"code\":-32603,\"message\":\"Internal error\"}}",
    new String(accidental, UTF_8));
```

A **deliberate** error is a `JsonRpcException` — thrown, or carried by a failed `Promise`; the two routes are
identical, and a `throws JsonRpcException` clause on the interface is not a contract violation. Its
`JsonRpcError` is the contract: code, message and `data` are re-emitted verbatim, `data`'s bytes included. The
exception's *own* message stays local and is never copied into the error object — a one-way valve, because
`MalformedDataException`'s message embeds the remaining input, and echoing it would hand a peer's bytes to
that peer's counterparty.

Anything **else** is exactly `-32603 Internal error`: no `data`, no class name, no message fragment, no stack
frame anywhere in the output. That is asserted byte-for-byte, negatives included.

A notification is the one case with nowhere to put a failure — §4.1 forbids answering it. Its failure goes to
`withFailureHandler(...)`, which defaults to `Reactor.logFatalError`; nothing is written to the wire and
nothing is swallowed.

At the caller, both arrive as a `JsonRpcException`:

```java
JsonRpcException deliberate = (JsonRpcException) awaitException(payments.charge(1000));
assertEquals(429, deliberate.getError().code());
assertEquals("Too many requests", deliberate.getError().message());

JsonRpcException accidental = (JsonRpcException) awaitException(payments.charge(1));
assertEquals(-32603, accidental.getError().code());
```

### The transport SPI

`JsonRpcTransport` is a **duplex, message-oriented** channel carrying complete JSON-RPC documents as
contiguous `byte[]`: outbound is `send(byte[])`, inbound is a `Listener` the transport pushes to. It is
deliberately not `Promise<byte[]> request(byte[])` — that shape is marginally simpler for HTTP and makes a
server&rarr;client call impossible without a redesign. It does **not** extend `Reactive`: an implementation is
free to be reactive, but an in-memory one must not be forced to carry a reactor it never uses.

Serving a dispatcher over one is the wiring below, and that is all of it:

```java
JsonRpcDispatcher dispatcher = JsonRpcDispatcher.builder(Reactor.getCurrentReactor())
    .withService(UserApi.class, new UserApiImpl())
    .build();

// `transport` is whichever JsonRpcTransport you plug in; this one is the in-memory double
InMemoryTransport transport = InMemoryTransport.create(document -> Promise.of(new byte[0]));

transport.setListener(new JsonRpcTransport.Listener() {
    @Override
    public void onDocument(byte[] document) {
        // one complete, contiguous document — the transport joined the pieces before calling us
        dispatcher.dispatch(document).whenResult(response -> {
            // zero bytes is how "no response document" is spelled: a notification, or a batch of
            // only notifications. It must never reach the wire (obligation 3)
            if (response.length != 0) transport.send(response);
        });
    }

    @Override
    public void onClosed(@Nullable Exception e) {
        // exactly once, whether the close was local, remote, or a failure of the medium
    }
});
```

The seven obligations an implementor takes on, in full in
[`JsonRpcTransport`](src/main/java/io/activej/jsonrpc/transport/JsonRpcTransport.java)'s Javadoc:

1. **Join before decoding.** A document handed to `onDocument` is complete and contiguous. The decoder leaves
   `params` / `result` / `error.data` as index pairs into *the array it was given*, and those indices do not
   survive a buffer refill.
2. **Bound the accumulation, not the result.** Apply `JsonRpcLimits.MAX_BODY_SIZE` *during* accumulation and
   refuse as soon as the running total crosses it. The decoder re-applies it, but as a last line of defence.
3. **Never deliver a zero-length document.** "No response" is the absence of a call, not an empty one.
4. **`send`'s promise means *written*, not *answered*.** Correlating an answer is the caller's job, by `id`.
5. **Assume nothing about pairing or order.** One sent need not produce one received; responses may arrive in
   any order relative to the requests that caused them.
6. **Closing is idempotent and reported exactly once.** `close()` / `closeEx(...)` may be called any number of
   times; `Listener.onClosed` fires once, whether the close was local, remote or a failure of the medium.
7. **Everything transport-specific stays inside the implementation.** `ByteBuf` ownership, framing, connection
   establishment, reconnection and lifetime are all yours, and none of them appears in this interface —
   `JsonRpcTransportBoundaryTest` fails the build if a transport-specific type is ever named in this package.

`byte[]` rather than a pooled buffer is a deliberate trade: the decoder needs one contiguous array, so the copy
exists wherever the boundary is drawn, and drawing it here keeps buffer ownership — and the recycling
obligation that comes with it — inside each transport, which is where the knowledge of when a buffer may be
released actually lives.

### Inherit the conformance suite

A transport author does not write conformance tests. Extend `AbstractTransportConformanceTest`, supply a
transport, and inherit the whole JSON-RPC 2.0 suite — feature 01's conformance vectors, replayed end to end
through a real dispatcher. The module's own subject is
`InMemoryTransportConformanceTest extends AbstractTransportConformanceTest`, and this is the whole of its
required half:

```java
@Override
protected JsonRpcTransport createTransport(JsonRpcDispatcher peer) {
    // Peer is Promise<byte[]> respond(byte[]), which is exactly dispatch(byte[])'s shape
    return InMemoryTransport.create(peer::dispatch);
}
```

| Member | Obligation |
|---|---|
| `createTransport(JsonRpcDispatcher peer)` | **required** — a transport joined to `peer`, on which the harness plays the *client* side |
| `skippedVectors()` | optional — vectors this transport cannot carry, **named individually**. Every name must be a real vector, so a stale skip fails rather than hiding a vector that would otherwise run |
| `awaitDelivery()` | optional — for a transport that still has work outstanding once the reactor has gone idle |
| `createReorderableTransport(...)` | optional — a double that can hold and reorder inbound documents. Without it, the reordering test reports as *skipped* rather than as passed |

The harness lives in this module's **test** sources; a transport implemented in another module reaches it
through a `test-jar` dependency on `activej-jsonrpc`, which this POM does not attach today.

The dispatcher, the service interface behind it and the three comparison rules are the harness's and are not
overridable: a subject that could choose what `subtract` means, or how a response is compared, would be
conforming to itself. A skip is a statement about the *transport* and belongs in a comment next to the name —
"this transport frames documents at 64 kB, so `envelope-too-large` cannot reach the decoder" is a reason; "it
fails" is not.

## What this module is not

| You want | Where it lives |
|---|---|
| An annotated Java interface, a dispatcher, a client proxy | **here** — [The service layer](#the-service-layer) |
| HTTP / WebSocket / TCP transport | not here — a later feature. The SPI it implements is [here](#the-transport-spi) |
| Automatic `JsonCodec` derivation for a `record` | `activej-json` |
| Per-call timeouts, in-flight bounds | not here — a later feature |
| A DI module, JMX, a launcher | not here — a later feature |

For an ActiveJ-to-ActiveJ binary protocol, use `activej-rpc` instead — it is faster and in the
default build. This module exists for interoperability with clients that are not ActiveJ.
